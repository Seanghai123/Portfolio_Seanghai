NUM-Digital-Scheduler

Academic class-scheduling system · NUM Digital Full-Stack Course, Group 2 · 2025 — team project, my part: login page

Built by a 5-person front-end team (plus a back-end team) during the National University of Management's Basic IT / Full-Stack Course, NUM-Digital-Scheduler solves a real problem the university had: coordinating class schedules, rooms, and instructor assignments without constant back-and-forth and double-bookings. Admins create and update class schedules, assign rooms and instructors, resolve scheduling conflicts, and export the full schedule as a PDF. Instructors view their assigned classes, download their own schedule, and submit change requests when a room or time needs to shift.

Next.jsReactTailwind CSS Java Spring BootPostgreSQLREST APIJWT Auth

My role — Front-End Developer (Login Page)

  • Built the login page in Next.js/React, wired to the Spring Boot auth API (paired with teammate Korng Sovanreach on this page)
  • Handled the login form UI, validation states, and error handling for the sign-in flow
  • Styled the page with Tailwind CSS to match the rest of the team's admin/instructor interface

What I picked up from the team's back-end work

  • Spring Boot's layered MVC pattern — Controller → Service → Repository — while collaborating with the back-end team
  • Reading and consuming a full REST API surface (auth, schedules, classes, rooms, instructors, notifications, OTP-based password reset)
  • Relational schema design basics: how classes, rooms, shifts, instructors, and change-requests relate in PostgreSQL

The dashboard, class/room management, and drag-and-drop schedule assignment shown below were built by the rest of the 5-person front-end team (Uy Chakriya, Touch Vengkorng,Bun menghong, Yoeun Panha, and Korng Sovanreach) — included here to show what the finished product looks like.

Banking Management System

Group project ("C# LoveYou", 5 members) · C# Windows Forms course · 2026

A desktop banking system built in C# Windows Forms with a SQL Server database, split across three roles — Admin, Staff, and Customer — so each person only sees what their job needs. Customers check balances and recent activity, staff open accounts and handle day-to-day transactions, and admins oversee the whole system, users, and financial reporting. I worked with four classmates on the system, and my part covered the technology explanation and the staff-facing side of the app.

C#Windows FormsSQL ServerADO.NET.NET Framework

My part of the presentation

  • Explained the technology stack to the class: why C# Windows Forms for the UI, SQL Server for the database, and ADO.NET as the bridge between them
  • Presented the Staff / Employee Dashboard: summary cards for total customers, accounts, employees, and transactions, plus a live table of recent activity
  • Walked through the staff-side Manage Customers screen — search, add, edit, and deactivate customer records

What the full system does

  • Login and registration with masked password fields and role-based access (Admin / Staff / Customer)
  • Customers view their balance, recent transactions, and profile from their own dashboard
  • Admins manage accounts, transactions, users, and export financial reports to PDF or Excel
